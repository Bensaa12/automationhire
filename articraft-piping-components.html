How to brief a component generation project

A good brief takes 10 minutes and saves two rounds of iteration. Include:

  • Component type and class — e.g. DN100 Class 300 trunnion-mounted ball valve, ASME B16.10 F-F
  • Material and trim — e.g. A216 WCB body, A182 F316 trim, RPTFE seats
  • Connection type at each port — RF flanged, BW, SW, threaded
  • Operator / actuator — handwheel, lever, gearbox, or pneumatic actuator (supply pressure and fail position if actuated)
  • Manufacturer data sheet — PDF or STEP from vendor if available; we model from scratch if not
  • Required output formats — STEP only, STEP + URDF, or full pack including Plant 3D .pcat
  • Quantity — single component, a series (DN25 through DN200 in one class), or a full catalog pack
  • Target CAD platform — Plant 3D version, SolidWorks year, or other

About Articraft — the technology behind the generation

Articraft is an open-source agentic 3D asset generation system built on CadQuery, which is a Python API over the OpenCascade Technology (OCCT) geometry kernel — the same kernel used by FreeCAD, Salome, and several commercial CAD packages. It was originally developed for large-scale articulated 3D dataset generation (robotics training data), but its output characteristics — dimensionally accurate parametric solids with articulated joints — translate directly to engineering component authoring.

What Articraft produces for each piping component:

  • A parametric solid model authored in Python (CadQuery). The code is version-controlled, reproducible, and can be parameterised to generate a full size series (DN25–DN200 in one run).
  • An articulated assembly where moving parts are separate bodies with defined joint axes, travel limits, and parent-child relationships. A gate valve has three bodies: body + stem + gate. The handwheel is a fourth. The URDF carries the joint definitions.
  • STEP AP214 / AP242 export at OCCT native precision — no mesh approximation, true B-rep surface.
  • A URDF file with link inertials, collision geometry, and joint limits — ready for ROS, Gazebo, Isaac Sim, or a client's digital-twin platform.
  • Mesh exports (OBJ + MTL, GLTF, STL) from the same geometry for downstream visualisation.

What Articraft does not produce natively: Plant 3D .pcat entries, OpenPlant catalog XML, or SolidWorks Routing library files. These are written by the UK specialist as the integration layer — mapping the STEP geometry into the target CAD system's spec format. That integration step typically adds 30–60 minutes per component and is included in the catalog pack rates above.

Frequently asked questions

Can Articraft generate components to exact manufacturer dimensions?
Yes, when a manufacturer data sheet or vendor STEP is provided. The specialist reads the published dimensional tables and builds the CadQuery model to match face-to-face, bore, flange OD, bolt-circle, and overall envelope exactly. Where a data sheet specifies a dimension as “per ASME B16.10” or similar, the standard table is used. The code is delivered alongside the STEP so you can verify every dimension.
How does the Plant 3D .pcat integration work?
The .pcat (Plant 3D catalog) file maps the 3D geometry to port definitions (size, type, end condition, flow direction), dimension parameters, and spec-line entries. The UK specialist writes this by hand using the Plant 3D Content Builder, referencing the STEP geometry ports. The result drops into your project catalog alongside any existing content. It requires your Plant 3D version to be specified (2024, 2025, or 2026) because the content builder format differs between releases.
Can I get a full size series rather than just one bore size?
Yes — this is one of the primary advantages of parametric CadQuery generation. The code takes bore and pressure class as inputs, so running the script for DN25 through DN200 (8 sizes) in Class 300 produces 8 STEP files, 8 URDF files, and 8 .pcat entries in a single generation run. Pricing for series is substantially lower per-component than single-piece orders. Specify the full size range in your brief and the quote will reflect it.
What is URDF and why would a piping team need it?
URDF (Unified Robot Description Format) is the standard format for articulated assembly definitions used in robotics simulation (ROS / Gazebo) and increasingly in industrial digital twins (Siemens Industrial Metaverse, NVIDIA Omniverse / Isaac Sim, Ansys Twin Builder). If your client or project team is building a plant digital twin, they need articulated valve assemblies in URDF so that operators can simulate open/close cycles, handwheel torque, and maintenance access in the virtual model. You can also ignore URDF entirely if you only need STEP for CAD.
Can you generate non-standard or proprietary components?
Yes — Articraft generates from a description, not a library lookup, so novel or proprietary geometries are feasible. We have generated bespoke instrument bodies, composite-lined fittings, jacketed spool pieces, and skid-level sub-assemblies from client data sheets. The only requirement is that the geometry can be described parametrically. Organic or free-form shapes (e.g. a cast pump volute with complex internal passages) are harder and may need a hybrid approach with mesh tools.
How accurate are the components for stress analysis?
The STEP geometry exported by Articraft + CadQuery is a true B-rep solid (not a mesh approximation), so it imports cleanly into FEA tools (ANSYS, Abaqus, Simcenter) for stress analysis. Wall thickness, bore, and external envelope are parametric, so ASME B31.3 minimum-wall calculations can be baked into the generation script. However, internal details like weld preparations, notch radii, and casting-grade thickness variations should be confirmed against the manufacturer's DXF or STEP if fatigue or pressure-vessel certification is required.

Do you work with OpenPlant or SmartPlant as target systems?
Yes. The STEP geometry is CAD-system-agnostic. For OpenPlant (Bentley), the integration layer writes OpenPlant Component Builder catalog XML instead of .pcat. For SmartPlant 3D / Smart 3D (Hexagon), it generates the material catalog entry and reference data in the Smart 3D format. These integrations take more specialist time than Plant 3D (the tooling is less scriptable) and are priced accordingly. Specify your target system when you submit the brief.
